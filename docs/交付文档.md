## 一、系统概览

两个页面、一套数据、两条发布通道。

| 页面 | 路径 | 用途 | 数据来源 |
|---|---|---|---|
| **在途看板（总页面）** | `/`（`index.html`） | 全站首页「总览」+ 在途概览、周计划、逾期、产能、产线时效、准交率、交叉分析 | `data.json`（构建时内联进 HTML） |
| **采购管理台** | `/console/` | SKU 映射表、申请单匹配、待下单汇总、未匹配补录、漏下单核查 | `console/weekly.json`、`map.json`、`price.json` |

两个页面共享品牌与视觉体系，但数据源不同：

- 看板读 `data.json`（金蝶采购订单全量）。
- 管理台读 `weekly.json`（金蝶采购申请单，申请单驱动）。
- **总览只在看板里**，管理台不再有总览页签。

## 三、数据管道

```
金蝶云星空
   │  每日 09:15 / 14:30 / 17:45 自动导出
   ▼
src/*.xlsx（4 张）
   │
   ├─ clean.py ──────────────► data.json
   │                              │
   │                              ▼
   │                          build.py ──► index.html（内联 echarts + 数据）
   │
   └─ build_console_data.py ──► console/weekly.json、apply.csv、overview.json
                                  │
                                  ▼
                          _deploy_web/（发布包）──► 云端 supply-console
```

**关键约定**

- `run.py` 是唯一入口：`python run.py` = clean + build。
- `build.py` 会顺带调用待下单构建，所以日常只需跑 `run.py`。
- 任何对 `index.html` 的手工修改都会在下次 `build.py` 时丢失——**必须改 `index.template.html`**。

## 五、版本管理与回滚（重点）

### 5.1 三层留痕

| 层级 | 位置 | 能做什么 |
|---|---|---|
| 页面快照 | `versions/vX.Y.Z_DATE/` | 双击 `index.html` 看当时完整页面（含内联数据，零依赖） |
| 源码 | git commit + tag `vX.Y.Z` | `git checkout v2.0.0` 精确回到该版本源码 |
| 数据 | `src/` 历史 + 快照内联数据 | `git log -- src/` 追溯源表变化 |

### 5.2 新增一个版本

```bash
cd supply-dashboard
python archive_version.py --type minor \
  --title "一句话摘要" \
  --desc "具体改了什么" \
  --reason "为什么改" \
  --impact "影响哪些页面/口径/文件"
```

脚本会：抓取当前页面快照 → 复制 `console/` 与 `index.template.html` → 写 `delivery-note.md` →
更新 `versions/INDEX.md` 与记忆档案 → commit + push → 打 `vX.Y.Z` 标签。

`--type` 选 `major`（结构性）/ `minor`（功能）/ `patch`（小修）/ `before`（改前存档）。

### 5.3 回滚线上到某个版本

**方式 A：用快照文件覆盖（最快）**

```bash
cd supply-dashboard
cp -f versions/v1.6.2_2026-10-20/index.html            index.html
cp -f versions/v1.6.2_2026-10-20/console/index.html    console/index.html
# 再走一遍 4.2 的同步 + 发布
```

**方式 B：用 git 标签**

```bash
git checkout v1.6.2 -- index.html index.template.html console/index.html
python run.py          # 让数据回到最新（若只想回滚界面而保留数据）
```

**方式 C：整体回到旧版本**

```bash
git checkout v1.6.2
# 注意：会同时回滚数据处理逻辑，之后需要重新跑同步
```

> 回滚后务必核对：`data.json` 的 `meta.updated_at` 是否合理，待下单行数/件数是否与源表一致。

## 六、常见操作

| 场景 | 做法 |
|---|---|
| 改看板界面 | 改 `index.template.html` → `python run.py` → 发布 |
| 改管理台界面 | 直接改 `console/index.html`（无构建）→ 发布 |
| 只重建不发金蝶 | `python run.py`（跳过导出） |
| 一键刷新（含导出） | 双击 `refresh_all.bat`；`refresh_all.bat skip` 跳过导出 |
| 手动补录待下单 | 管理台「周计划 → 手动补录待下单」，只写本机 localStorage |
| 改映射/报价 | 管理台需先点「只读模式」输入口令 `hy2026` 解锁 |

## 七、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 改了页面但线上没变 | 未发布 / 浏览器缓存 | 重新发布 + `Ctrl+Shift+R`；用 4.2 的 md5 比对 |
| 改了 `index.html` 后次日复原 | 动了构建产物 | 改 `index.template.html` 再 `python run.py` |
| 总览页仍是旧版 | 发布包没同步 | 检查 `_deploy_web/index.html` 的 md5 |
| 待下单数量对不上 | 读源表时把「合计」行也算进去了 | 求和必须剔除单据编号为空的行，否则正好翻倍 |
| 云端改动没保存 | 只读模式未解锁 / 云端不可达 | 看顶部徽标文案，点它可重试 |
| 页面 403 | 缺 `?sharecode=TXN5CQCX35` | 补上分享码 |

## 八、口径速查

| 指标 | 定义 |
|---|---|
| 在途（剩余收料） | Σ`remain`，可按交货月筛选 |
| 逾期 | `overdue_days > 0` 的剩余量 |
| 待下单 | 采购申请单「剩余数量 > 0」且单据未关闭/未作废 |
| 准交率 | Σ(收料日期 ≤ 采购订单交货日期 的收料量) ÷ Σ收料总量 |
| 完成率 | 已收 ÷ 采购总量 |
| 负荷率 | 该月在途 ÷ 供应商月产能（月产能不跨月累加） |
| 排除项 | 物料编码含 `VYTK` 的一律不计 |
