# 供应链在途数据 · 动态可视化看板

> 单 HTML 文件 · 内联全部 JS/CSS/数据 · 前端零后端、零 API · 双击即用 · GitHub Pages 自动部署
>
> 线上地址：**https://yikeqingsongguo.github.io/HY.supply-chain-management/**

## 一、架构约束（已满足）

- **单 HTML 文件**：`index.html` 内联了 ECharts 库、字体与 `data.json`（由 `build.py` 注入），双击即可在浏览器打开，无需任何服务器。
- **零后端 / 零 API**：所有计算在前端完成；数据全部随页面内联，无任何外部请求。
- **数据流水线**：`clean.py` 解析 Excel 源表 → 清洗 → 产出 `data.json`；`build.py` 把库、字体与数据注入模板生成 `index.html`。

## 二、目录结构

```
supply-dashboard/
```

## 三、★ 在 GitHub 网站更新数据（最常用）

> 三个源表都在仓库的 **`src/` 目录**里。更新数据 = 用新文件**覆盖**它。

### 采购订单 / 产能（两个简单）

1. 浏览器打开：**https://github.com/yikeqingsongguo/HY.supply-chain-management/tree/main/src**
   （也可从仓库首页点进 `src` 文件夹）
2. 右上角点 **`Add file` ▾ → `Upload files`**
3. 把本地文件拖进虚线框。**文件名必须与仓库里已有的完全一致**：
   - 采购订单 → `采购订单.xlsx`
   - 产能 → `产能.xlsx`

   ⚠️ ERP 导出的文件名常带时间戳（如 `采购订单_2026091814411488_3968810.xlsx`），
   **请先在本地改名为 `采购订单.xlsx` 再上传**，不要直接传原名。
4. 页面下方 `Commit changes` 的说明随便填（如 `更新采购订单 9.18`），点绿色 **`Commit changes`**。
5. 刷新仓库顶部 **`Actions`** 页签，等最新一条跑成绿色 ✅（约 1 分钟），再看板刷新即为最新数据。

### 周计划（多一步：先删旧）

周计划表的**文件名里的日期决定它归属哪个月**（用于「本月 / 下月」筛选），所以要保留日期：

1. 本地文件名保持形如 `9.23周计划-9.23.xlsx`（必须含「周计划」）。
2. **先删掉上一周的旧文件**：打开 `src/` 里的旧周计划 → 右上角垃圾桶图标 → `Commit changes`。
3. 再按上面同样步骤上传新的一周文件。

> 如果忘了删旧文件，`clean.py` 会检测到"匹配到多份周计划"并**故意让构建失败**（红色 ❌），
> 报错信息会列出所有候选文件。这是防错设计——宁可失败，也不用错数据。

### 三条铁律（避免"看着成功、其实没更新"）

1. **一定传进 `src/` 目录**，不要传到仓库根目录（根目录的文件流水线不会读）。
2. 采购订单 / 产能**必须用同名文件覆盖**，不要新增带日期的文件。
   （否则旧文件会继续被使用，而 Actions 仍显示 ✅——这是最容易踩的坑。）
3. **判断是否真的更新了**：看 Actions 日志里的 `Σ采购数量` 是否与源表「合计」行一致，
   或直接看看板 KPI 有没有变化。**页面右上角的时间是「构建时间」，不能作为数据已更新的依据。**

### 本地更新（推荐，可立即看到结果）

1. 把新的三个 Excel 按上面的命名规则放进 `src/`（覆盖同名文件）。
2. **双击 `refresh.bat`**（Mac/Linux：`bash refresh.sh`）→ 自动重跑清洗与构建并打开浏览器。
3. 想发布上去：`git add -A && git commit -m "更新数据" && git push origin main`

## 四、数据清洗规则

| 步骤 | 规则 | 说明 |
|---|---|---|
| ① 删空单 | `单据编号` 为空/空白，或 `单据类型 == '合计'` | 计 `dropped_po`；**但会先抓下「合计」行数值用于自检** |
| ② 业务关闭行 | `业务关闭 == '业务关闭'` 的**行保留**，并打 `biz_closed` 标记 | 这些是"已收完并关单"的行，剩余收料恒为 0 → 保留不影响在途口径，却能保住其采购量与已收量。详见下方「为什么」 |
| ③ SPU 取码 | `SPU = 物料编码` 仅留数字、取前 4 位 | `spu_of()` |
| ④ 交货日期 | 归一化 `YYYY-M-D` | `fmt_date()` |
| ⑤ 月份推导 | 由交货日期「月」→ `M月`；无日期记 `—` | 周计划按文件名日期 +31 天 |
| ⑥ 标签取源 | 产线标签 / 时效标签 = 源表同名列（空则留空） | 不臆造 |
| ⑦ 字段映射 | 供应商简称 = 产能表.供应商简称（按供应商全称 join） | 同时得到采购负责人 / 月产能 |
| ⑧ **自检** | 汇总的 Σ采购数量 / Σ已收料 / Σ剩余收料 必须等于源表「合计」行 | 不一致则**构建失败**（exit 1） |

### 「业务关闭行保留」的原因（重要）

ERP 导出里，某些**已收完并关单**的行会标记为 `业务关闭`。它们的特点是
`剩余收料数量 = 0`、`累计收料数量 = 采购数量`。

曾经这里把整行删除，后果是**系统性低估**：

- 采购总量少算 125,618（1,126,808 → 1,001,190）
- 已收料少算 125,618（287,187 → 161,569）
- 完成率被压低：**25.5% 被算成 16.1%**
- 单张订单也会错：`CGDD012512` 应显示 采购 19,350 / 已收 7,500，却显示成 11,850 / 0

因为 `剩余收料 = 0`，保留它们**完全不影响**在途、逾期、产能负荷等口径
（Σ剩余收料 839,621 前后一致），只是把采购量与已收量补回来。
`index.html` 的明细里这类行会显示「已关闭」标签以便识别。

### 计算口径

- **完成率** = 已收料 ÷ 采购数量（已收料 = 采购数量 − 剩余收料数量）
- **逾期** = 交货日期 < 今天 且 剩余收料 > 0
- **在途 / 剩余收料**：只与 `剩余收料数量` 有关，不受已关单行影响
- **状态**：已关单行 → 「已关闭」；其余 → 「剩N天 / 逾期N天 / 待交期 / 已完成」
- **周产能** = 月有效产能 ÷ 该月 ISO 周数（非 ÷4）
- **核心供应商**：忆恩、佳俊、同光、拿可、宝莎、贝瑞卡、浩川、骏航、思哲

## 五、页面与功能

1. **在途概览**：KPI 卡片 2 行×4 张；整体在途分布柱状图（核心/普通切换，点击下钻）；Top8 供应商占比环形图（在途剩余/已收料/采购总量/当月/下月）；供应商月度订单表（本月/下月数字可点击）+ 每日需交趋势折线面积图（本月/下月切换）。
2. **供应商分析**：产线订单条形图；时效/产线标签气泡图（点击下钻）；各产线收料与负荷汇总表；时效标签收料与负荷汇总表。
3. **产能负荷分析**：负荷率分布（点击联动详情表，高度与图一致）；超额/饱和/空闲状态分布；核心 vs 普通产能占比环形图；供应商产能占比排序。支持 本月/下月 与 核心/普通 筛选。
4. **周数据计划**：分界值可调（默认 5000，步长 500）；图 A / 图 B；堆叠柱（在途剩余 + 周计划斜纹）；各供应商本周计划数量汇总表；支持 本月/下月 与 核心/普通 筛选。
5. **逾期分析**：逾期 KPI；逾期供应商 TOP；逾期天数分布；逾期供应商汇总表（一行一家、默认数量降序、可筛选）。
6. **交叉分析**：全局切片器（供应商/月份/产线/时效/物料名称/SPU）+ 文本搜索；供应商×月份热力图（TOP20/全部/核心）；工厂逾期数量 TOP。

**下钻体系统一为两级**：`订单汇总（一行 = 一个采购订单号，含 SPU 数 / 订单行数）` → `SKU 明细`（物料名称 / 规格型号 / SKU / 数量 / 已收 / 剩余 / 交货日期 / 状态）。
抽屉支持**返回上一级**（导航栈），宽度 1260px。

## 六、UI 主题（Claymorphism 黏土拟态）

- 画布 `#F4F1FA` 淡紫白；卡片 glass-clay（半透明白 + `backdrop-filter: blur`）
- 4 层阴影栈：`--clay-card / --clay-card-hover / --clay-deep / --clay-btn / --clay-pressed`
- 糖果色：`#7C3AED` 紫 / `#DB2777` 玫红 / `#0EA5E9` 天蓝 / `#10B981` 翡翠 / `#F59E0B` 琥珀
- 超圆角 20/24/32/48，无尖角；按钮/选项卡渐变凸起，hover 上浮、active squish
- 字体：Nunito（标题/数字）+ DM Sans（正文），**latin 子集 woff2 已 base64 内联（零外链）**
- 动画：页面淡入、KPI 卡片错峰上浮、背景光斑浮动；`prefers-reduced-motion` 下全部关闭
- 响应式：≤900px 折叠为汉堡导航；表格容器横向滚动；卡片 4/3/2 列断点

## 七、GitHub Pages 自动部署

1. 仓库 **Settings → Pages → Build and deployment → Source** 选 **`GitHub Actions`**（只需设置一次）。
2. 之后每次推送到 `main` 分支即自动：`clean.py` → `build.py` → 发布到 Pages。
3. 也可在 **Actions → Deploy Supply-Chain Dashboard → Run workflow** 手动触发。
4. 线上地址：**https://yikeqingsongguo.github.io/HY.supply-chain-management/**

> 注意：Pages 只发布 `_site/`（仅含 `index.html`）——`src/*.xlsx` 源表不会被发布成公开站点。
> 但仓库本身是 Public，源表在仓库里仍是可读的；如需保密请改用私有仓库 + Cloudflare Pages 等方案。

- **`src/` 源表唯一性检查**：同一关键字匹配到多份 xlsx 时立即报错中止（防止静默使用旧文件）。
- **`headless_test.js`**：jsdom 无头实跑，断言 6 个页面、16 个图表、两级下钻 + 返回上一级、
